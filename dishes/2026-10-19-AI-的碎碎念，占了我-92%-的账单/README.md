## 📝 摘要

今早，赶在写稿之前，我拿一段分页 bug 的描述去问推理模型。

问题本身不难：第 1 页正常，第 3 页开始数据重复，让它给原因和排查步骤。

它开始想。我把请求挂在那儿等，等的时间不短。

最后返回的答案位置是空的。

不是报错。我去翻返回体里的 usage：completion_tokens 2000，reasoning_tokens 2000。

思考把整份输出预算吃干净了，一个字的答案都没剩下。

我不服气，把 max_tokens 提到 6000，同一个问题再问一遍。

这次它想了 13956 个字符，其中 3419 个汉字，中间还写了一句 "Let's craft detailed but concise answer"。

然后它又没写答案。

我回头把那两千字的思考读了一遍，读到几件挺荒谬的事。

我用中文提问，它前半程用英文想。英文想到一半才切回中文，切换的那句是"需要控制篇幅，Desired oververbosity 5，中文回答"。

它在给自己定篇幅。定完之后，预算没了。

中间它还在跟自己商量要不要把"缓存"算成原因之一，写了又划掉，划掉又写回来，最后补了一句"缓存作为补充"。

一道不算难的排查题，它花了八千个 token 在自我协商上。

为了确认这不是个例，我又丢给它一道一句话就能答的乘法题：1234 乘 5678。

这次它写完了。输出 159 个 token，其中 146 个是思考，答案是 13 个 token。

为了写出十几个字，它先把草稿念了一遍。

标题里那个 92%，就是这道题量出来的。
