## 📝 摘要

周一我在公司一个 Java 项目里让 Agent 修一个分页 bug。

仓库五千多个文件。它没急着改代码，先把半个仓库读进上下文，再慢慢开始想。

改得对。账单不对：一个本来二十分钟的活，烧掉将近三十万 token。

我当时的结论是"模型不够聪明，绕了远路"。昨天看完 Qwen4-Max 的发布材料，我把结论改了——绕远路的不是它，是我。我扔给它一座仓库，让它自己决定读哪些。

那个 bug 本身我后来自己改，用了六分钟，动了三行。

模型花了二十分钟，其中十九分钟在读跟我无关的文件：一个十年前的历史迁移脚本、三个早就不用的配置文件、一堆带注释的旧代码。

它没做错。我给它的信息里没写"这些不要读"，它就无法判断哪些有用。

三十万 token 里，真正干活的大概只有两万。

昨天阿里发布的东西，恰好把这个问题摆到了明面上：一个模型如果能把"读多少"也当成任务的一部分来管，账单会变成什么样。
