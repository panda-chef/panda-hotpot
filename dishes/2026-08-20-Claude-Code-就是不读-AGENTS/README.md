## 📝 摘要

我的日常工作，是两个命令行窗口并排开着。

左边是 Claude Code，右边是 Codex。同一个项目，同一个仓库，两个 AI 轮流给我写代码。

它们都挺聪明，但有个毛病，让我烦了整整一年。

它们读的"使用说明书"，不是同一份。

Claude Code 认 CLAUDE.md，Codex 认 AGENTS.md。两份文件，内容九成一样，剩下那一成，是我手滑改漏的地方。

这事我第一次撞上，是换新电脑那次。

装机、配环境、把常用工具一个个装回来。装到 AI 编程工具这块，我卡住了。

Claude Code 要我写 CLAUDE.md，Codex 要我写 AGENTS.md。我盯着两个几乎一样的文件名，突然意识到：以后每条规则，我都得写两遍。

上周我改了一条规则："提交前必须跑一遍测试"。

我只改了 CLAUDE.md，忘了 AGENTS.md。

第二天 Codex 给我交了一堆没跑测试的代码，我在 review 的时候才发现，整整一个下午搭进去。

更气人的是，它还不是干砸了，是压根不知道这条规则存在。就像新来的实习生，没人告诉他规矩，他当然乱来。

那一刻我特别恼火：为什么就不能有个统一标准，让我只写一份？

结果昨天刷 HN，看到这个问题被顶到了首页。116 分，61 条评论。

一年了，还是没解决。
