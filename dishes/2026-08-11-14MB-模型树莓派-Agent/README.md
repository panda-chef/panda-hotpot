## 📝 摘要

上个月我把吃灰三年的树莓派 5 翻出来，想在上面跑个 AI agent。

不是那种"对着 API 发请求"的假 agent——是真的让它在本地听懂我的话、决定调用哪个工具、然后执行的那种。

试了三个方案。

FunctionGemma 270M，太大了。模型文件下载了 500 多 MB，树莓派的 SD 卡差点塞不下。加载花了 40 秒，CPU 风扇直接起飞。推理速度不到 10 token/s——我说一句"打开客厅的灯"，它要愣三秒才开始反应。那个延迟，比你自己走过去开灯还慢。

LFM2.5 230M，好一点。加载快了，推理也到了 20 token/s。但工具调用准确率只有六成。说"把客厅灯调到 50%"，它选对了函数，参数填成了 `brightness: 50`。还行。但说"客厅暗了一点"，它就懵了，返回了一个空响应。可用的场景太窄。

更小的模型——比如各种蒸馏版本——工具调用能力直接崩了。不是选错函数就是参数乱填。

最后我放弃了。结论是：端侧 agent 还没到实用阶段。要么太大跑不动，要么太小不靠谱。

直到昨天看到 HN 上一个 132 分的帖子。

Needle 2。

14MB。

不是我少打了个零——十四兆字节，一个完整的、能做工具调用的 agentic LLM。45M 参数，一个二进制文件，28MB 内存跑完整会话，树莓派 5 上解码速度 500 token/s。

我当时的心情是：这不科学。
