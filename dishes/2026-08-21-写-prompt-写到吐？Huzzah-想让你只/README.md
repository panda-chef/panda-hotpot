## 📝 摘要

上个礼拜，我在改一个 Java 老项目。

一个登录鉴权的重构，我改了三天。

不是代码难。是每次改动，我都要用英文重新描述一遍我想要什么。

"把这个 service 里的 token 校验抽出来，放到一个单独的 filter 里，保留原来的异常处理，日志格式别动……"

一句话讲不清，我就写两百字。两百字还讲不清，我再补一段。

到第三天，我盯着聊天窗口里滚动的几千字 prompt，突然觉得这事哪里不对。

我大致算了算，三天里我光是写 prompt，就写了快八千字，比那三天的代码改动加起来还多。

我明明会写代码。

为什么我要用这么啰嗦的方式，去求一个会写代码的机器，帮我写代码？

昨天，我在 Hacker News 上刷到一个帖子，直接冲到 200 分。

标题叫 Huzzah：一种用 AI 写代码的新方式。

作者 Daniel Vaughn 写的开头，跟我上面那段话几乎一模一样。

他说，2026 年前几个月爽爆了。coding agent 终于好到不用手写代码了。

然后蜜月期结束，他感到彻头彻尾的疲惫。

"我受够了用长篇英文描述我要对代码库做的每一个改动。"这是他的原话。

但他也不想回到全部手写代码的日子。

他说他需要鱼和熊掌都要。既要 AI 帮他写，又要重新掌控自己代码在干什么。

我读完文章第一个反应是：这哥们把我这几个月的憋屈，全说出来了。
