## 📝 摘要

上个月我接了个活，把老项目里的缓存模块理清楚。

我打开那个文件，愣了。

几千行，几乎全是 if 分支。一个特例套一个特例，特例上再盖一层异常。我顺着主流程往下读，读到第三层，就找不着北了。

这不是我手写的。是我让 Claude Code 一点点改出来的。

两周里我接了六个需求，每个都让它加个分支。它很听话，每次都加对了，还顺手补了单元测试。我几乎没认真看过它改的东西。

我点开 git log，看着那一排 commit，突然打了个冷颤。

我不理解这个文件了。

更可怕的是——那个本来会提醒我"该重构了"的东西，消失了。

***

这篇文章的灵感，来自昨天 Hacker News 上讨论度最高的一篇 AI 文章。作者是 Rodrigo Rosenfeld Rosas，一个资深工程师，标题叫《AI Agents and the Refactoring That Never Happens》——AI 智能体，和那场永远不会发生的重构。

它讲的这件事，我越读越点头。

这年头模型一个比一个能打：Gemini 3.8 Flash 昨天发布，官方说它在一项长程软件开发 benchmark 上超过多数更大的旗舰模型，价格只有零头。Qwen3.8-Max 昨天在代码竞技场冲到第二，把 Claude Opus 5 顶下去一名。AI 写代码，已经从"能用"变成"好用"。

代码越写越强，意味着我们身边的人，会越来越放心地把代码交给 agent 去写。

这恰恰是问题开始的地方。

为什么偏偏是现在？去年大家还只敢让 agent 写点小函数、补个测试。今年不一样了——模型在长程编程任务上，真能端到端解决复杂问题，成本还低到可以当日常。于是越来越多的团队，把整整一块业务逻辑、一个完整服务，都交给 agent 去长。

它写得越多，人理解得越少。那个用来叫停的警铃，就离得越远。等你想起来的时候，往往已经晚了大半年。
