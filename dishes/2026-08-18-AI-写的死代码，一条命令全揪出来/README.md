## 📝 摘要

今年年初，我接了个活：审计一个 Go 项目的代码库。

这个项目有点特别。它从头到尾都是 AI 写的，人类只负责 review。团队把 AI pair programming 用到了极致，每天让 Claude Code、Codex 这类工具生成几百上千行代码。

团队这一年引以为傲的，是交付速度翻了三倍。没人停下来问一句：这些代码，真的都是必需的吗？

我打开一看，傻了。

几千行代码，能编译，能跑，测试全绿。但里面有大量函数，从头到尾没有任何一个地方调用过。

`processLegacyOrder`，从来没被调用。`normalizeInputV2`，已经被 V3 取代，而 V3 又被 V4 取代。还有一堆 `getUserData` 这种名字的工具函数，整个项目里没有任何代码去碰它。

我是怎么发现的？说来有点丢人。

我先是被一个函数名勾住了，`normalizeInputV2`。心想，有 V2，那是不是还有 V1、V3？一搜，V1、V2、V3、V4 全齐了。再看调用关系，四个版本，没有一个在用。

那一刻我意识到，这活儿比我想的大得多。这哪里是审计，这是给代码库做尸检。

这些代码是「正确」的。它们只是「没用」。

这就是 AI 写代码最容易被忽略的坑。
