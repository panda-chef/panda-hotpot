## 📝 摘要

昨天半夜，我在一个五千多文件的 Java 仓库里改分页。

任务本身不复杂：一个分页参数从 Controller 一路传到 Mapper，中间经过七层，某一层的顺序错了。我让 AI 自己去翻，它读了三十几个文件，改了十一处，中途自己回滚过两次。

改完是对的。

但我记住的不是这个。是跑完那一刻，我看到用量曲线陡得像心电图的那个瞬间。

我们这行现在有个不太好意思说出口的成本焦虑：你越信任它，账单涨得越快。让它多读几个文件、多想两轮，都是钱。

所以今天早上刷到 Kimi K3.1 Pro 发布的时候，我第一个念头不是「又一个模型」，是「这玩意能不能替我把这笔钱省下来」。

翻完官方技术博客和第三方评测，结论比我预想的复杂，也比预想的有意思。
